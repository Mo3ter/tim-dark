# 排查注意事项

这是 AI 辅助分析过程中得到的实机经验，不是所有 TIM 版本的通用结论。欢迎提交可以复现的反例和修正。

## 先确认版本和原件

资源目录与 DLL 版本必须对应。基础构建针对 3.5.0.22149，独立输入和路径修复验证的是 3.4.8.22124。修改前保存原件；指令或代码洞校验不匹配时，应重新分析，不能删除校验继续运行。

## 颜色属性不一定是最终颜色

AutoColor 可能把 color 当作亮度输入。部分 alpha 为零的颜色仍可见；透明色键应保留。扫描器重叠命中同一颜色时，需按值偏移去重。

通用颜色转换无法判断所有控件语义。新覆盖规则应记录文件、属性、原值和实际效果，检查背景、文字、边框及强调色。

## 资源缓存与实际绘制要分别验证

TIM 可能使用旧皮肤缓存。build.ps1 会处理 rdo.cache 和 loginrdo.cache；测试时也应确认 TIM 已完全退出并加载新文件。

theme.xml 的修改未覆盖已测试区域，说明还需要检查其他资源和引擎调用。不要把一次无效果实验写成“所有版本都不读取该文件”。

## 二进制补丁必须保留原调用行为

除了栈平衡，还要检查寄存器、标志位、调用约定、被覆盖指令、跳转范围及代码洞空间。补丁应验证原指令，保留备份并提供还原路径。

arkGraphic 的共享画布接口可能处理文字以外的图形；GF 与 RichEdit 路径也可能被多个控件使用。不能只凭一个输入框正常就断言没有其他影响。

## 区分绘制异常与文件路径异常

本机图片粘贴失败时，剪贴板读取成功，但 RichOle 图片保存返回 Windows 错误 649。还原文字补丁后仍然失败；群聊收藏表情则涉及 Common.dll 的独立缓存路径。

这些记录支持本机路径异常的诊断，不能用于解释每一种图片或表情发送失败。完整证据与当前方案见 [路径修复说明](PASTE-PATH.md)。

## 修改签名 DLL 可能触发完整性检查

旧 KernelUtil.dll 磁盘补丁导致 Authenticode HashMismatch，实机记录到软件损坏提示。当前路径方案恢复原 DLL，只在启动阶段修改内存。短时验证正常，长期稳定性仍需观察。

基础引擎和独立输入补丁仍属于磁盘修改，应该分别验证其影响，不能把路径修复的结果扩展到全部补丁。

## 回归检查以实际使用为准

确认正在查看目标 TIM 窗口；不同截图方式可能得到不同内容。检查输入文字、图片粘贴、群聊收藏表情、文字与表情混合消息，以及重启后的结果。登录检查由用户处理。

自动测试检查部分脚本逻辑和补丁边界，不能替代界面和长期运行验证。诊断记录应区分观察、推断与已确认结果，公开前去除聊天和账号信息。
