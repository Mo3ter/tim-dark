# 资源格式与颜色路径

以下是借助 AI 分析并用本机样本验证的记录，主要资源样本来自 TIM 3.5.0.22149。它们不是完整的官方格式规范，欢迎补充样本、纠正推断和改进解析器。

## .rdb 资源容器

分析的资源包括 Res.rdb、Xtml.rdb、Themes/Default.rdb 和 Data.rdb。前三者包含本项目处理的皮肤资源；观察到的 Data.rdb 样本主要是头像和表情。

~~~text
0x00  16 字节  ASCII 魔数 "531E98204F8542F0"
0x10  i32      条目数
0x14  i64      头部大小（样本为 36）
0x1C  i64      名称区大小
0x24  索引条目：
      UTF-16LE 名称，以 NUL 结尾
      i64 数据偏移，相对头部大小 + 名称区大小
      i64 数据大小
后续为数据区
~~~

魔数是 16 个 ASCII 字节，不是把字符串解释成 8 个十六进制字节。

~~~powershell
python tools/rdb.py unpack 文件.rdb 输出目录
python tools/rdb.py pack 输出目录 文件.rdb --manifest 原始.rdb
~~~

原始清单用于保留条目顺序和名称。已观察样本在未修改内容时可以逐字节往返一致；这验证了这些样本的处理结果，不代表覆盖所有版本。

## .gft 图片容器

文件通常以 TGF 开头，内部包含 PNG。skinpatch.py 在 0x14 检查 NINE 标记；存在该标记时读取 0x10 的 PNG 偏移，否则查找 PNG 签名。偏移不可靠时也会尝试签名定位。

替换 PNG 时保留前面的容器头和九宫格信息。不同变体仍需用真实样本验证，不能假定每个文件的头部相同。

## .gmd 编译皮肤

目前按属性记录扫描，尚未实现完整控件树解析。

TD/TA 记录包含标记、版本字节、kind、零字节、字符串类型和 u16 长度。字符串载荷按 0xFF XOR (长度 AND 0xFF) 解码；观察到 ANSI 和 UTF-16LE 两种类型。紧凑记录使用单字节标签、u16 长度和类似编码的属性名载荷。

识别到属性名之后，扫描器读取 u32 值长度及对应值字节。颜色通常是 4 字节小端值。不同扫描路径可能命中同一个值，必须按值的绝对字节偏移去重。

## 颜色与自动文字颜色

颜色值通常按 0xAARRGGBB 解释，例如 0xFF1E1E1F 的 RGB 为 (30, 30, 31)。保留原 alpha 字节：观察到部分 alpha 为零的属性仍显示颜色，不能统一按透明处理。

MaskColor 等透明色键需要排除。gmdark.py 使用背景与文字分类规则，并对部分控件设置明确覆盖项；覆盖项应先于通用规则处理。

AutoColor 的裸 color 在已分析路径中是 GF::Util::Text::GetTextColor 的亮度输入，不是最终文字颜色。直接把输入设为白色，可能得到黑字。

## theme.xml 的验证范围

Default.rdb 中的 appframework/config/theme.xml 样本含 276 个具名颜色。修改它没有改变当时测试区域的正文颜色，因此不能仅靠这份文件完成换肤。该结果不能推出所有 TIM 版本或控件都不读取它。缓存中出现文件也不能证明某个控件使用它。

## 资源之外的绘制路径

已定位的 arkGraphic 画布颜色设置和 GF 的 GDI 文字绘制仍会传入黑色。基础构建脚本为这些调用生成代码洞补丁，保留必要的原指令行为。共享绘制函数可能影响其他控件，需要回归检查。

TIM 3.4.8 的待输入文字另走 riched20.dll 路径，具体记录见 [输入文字说明](INPUT-WHITE.md)。这些调用位置是版本相关的，不能作为跨版本固定地址使用。
